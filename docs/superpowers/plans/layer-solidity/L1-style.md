## Indicators added by the deep read

- **L1.10 Cross-backend precedence equivalence** (catches F1–F3): for every pair of declarations that can both hold (base × each variant kind × both write orders), the resolved value is identical on headless (native resolver) and in the browser (Web CSS) — generated pairs, compared via headless resolve vs. `getComputedStyle` in web-testing. Bound: 0 differences. And a written precedence rule in `docs/styling.md`, with Tailwind divergences listed.
- **L1.11 No silent swallowing**: every input byte of a style file is either part of an accepted item or covered by an error range (property: union of item ranges ∪ error ranges ∪ whitespace = whole input). Catches F4, F5.
- **L1.12 Shadowing is explicit**: redefining a built-in utility/variant or a duplicate definition is an error or an explicit opt-in (`@utility hidden !override`?) — test per case. Catches F6.
- **L1.13 Compile-time theme ≡ run-time theme**: for any style file, `Vocabulary::with_style_file(s).token_table()` equals the `TokenTable` built from `project_theme()` through `tokens::token_table`. Property over generated files. Catches F8.
- **L1.14 Numeric text is finite and in range**, or an error (F9–F11).
- **L1.15 Depth/length limits on every recursive value grammar** (F12); fuzz `parse_value(kind, _)` for every `ValueKind`.
- **L1.16 Diagnostic hygiene**: no string constant used in diagnostics contains `\s{2,}` (a source test over `capability.rs` and all `format!` literals). Catches F13.
- **L1.17 Display ⇄ parse round trip** for `Condition`, `StyleValue`, `Declaration` (the inspector and LSP show `Display` output as if it were source; `light:` and `min-[Npx]:` are printed but `light:` is not a parseable variant).
- **L1.18 Vendored-data integrity**: test hashing `vendor/tailwind-theme-*.css` against `VENDORED.md`.

## Q-loop (iteration 1)

- New *kind* of indicator surfaced: **semantic equivalence across realizations of the same declaration** (F1/F2) — not "does each backend apply the property" (L1.2) but "do all backends agree on *which* declaration wins". Added to the method as aspect 15, *cross-realization equivalence*, re-asked for every later layer that has more than one realization (layout, text, accessibility, input, events).
- New *kind*: **"silent acceptance"** — inputs that are neither valid nor rejected (F4, F6, F9, F10). Re-asked in every later parser and API as Q1f: *what invalid input is accepted without a diagnostic?*
