## Indicators added (part 3)

- **L3.0.6 Per-update cost is O(changed subtree)** (F30): snapshot + diff + layout time for a one-leaf change at 10⁵ nodes ≤ 2× the time at 10³ nodes (instruction count). Today ≈ linear in the whole tree; the indicator forces an incremental snapshot/diff (dirty-subtree tracking) or makes the ceiling explicit.
- **L3.0.7 Memory per node** (F30): tree + snapshot + cached component views ≤ a budgeted bytes/node (start from today's 3.6 KB measured), checked by `core_costs.rs`.
- **L3.1.12 Depth guard** (F31): `RenderError::TooDeep` at a documented depth chosen so the whole pipeline fits a 1 MiB stack with margin; test at that depth on a 1 MiB thread.
- **L3.10.8 Compact form completeness** (F32): every `TraceKind` variant round-trips through `encode_trace`/`decode` (a test iterating all variants).
- **L3.9.5 Wire is untrusted** (F33, F34, F42): events decoded from a wire are validated against the current tree (exists, enabled, visible, same session); `Foreign` kinds from a wire are allow-listed; every deserialized core type re-validates its invariants (`#[serde(try_from)]` for `CalendarDate`, controls, `NavigationStack`).
- **L3.9.6 Grant soundness** (F35): `allows_path` on canonicalized paths; property test with generated `..`/symlink paths; redirects re-checked against the grant.
- **L3.9.7 Service contract limits** (F36, F37): HTTP requests carry a timeout and a maximum body size, header values reject CR/LF/NUL; document writes are atomic (temp + rename + fsync); a test kills the process mid-write and finds the old or the new document.
- **L3.8.9 Restore never panics** (F38): fuzz `NavigationStack`/persisted envelopes with arbitrary JSON; restore yields the default, never a panic.
- **L3.9.8 Deep-link surface** (F39): routes are internal by default; routes reachable from outside are declared, and their parameters are typed (no raw `..` or `/` in a segment parameter).
- **L3.2.8 Store robustness** (F40): after a panic in `Store::update`, the next update applies (test); reading the store inside its own update is either supported or a documented error, not a `RefCell` panic.
- **L3.10.9 Privacy of diagnostics** (F41, plus L3-F5): crash reports, recordings, traces, and HTTP tapes contain no text-input value, keystroke of a redacted field, clipboard or drop payload, URL query, or response body unless explicitly opted in; a marker-string test across all four.
- **L3.4.12 Virtual list cost** (F43): layout time and memory for a virtual list are within 2× between 10³ and 10⁷ items.
- **L3.10.10 Release-mode environment** (F44): an inventory of every environment variable the framework reads, each marked dev-only (compiled out of release) or release (justified); a test greps for `env::var` and compares with the inventory.

| L3-RP2 ✅ | P2 (availability) | **The UI thread's task pool has no per-pass budget, so a task that yields by waking itself freezes the window for good.** `LocalPool::run_until_stalled` loops until a sweep makes no progress, and a task that was ready and polled counts as progress even if it returns `Pending` after waking itself. That is the `yield_now` idiom, the usual way to keep long work cooperative (`tokio::task::yield_now`, `futures_lite::future::yield_now`). Such a task is polled again in the next sweep of the *same* call, so control never returns to the host's message loop: no paint, no input, no close. The component tree uses this pool as its local executor (`core/src/component/tree.rs:265`). Reproduced: one `run_until_stalled` call polled a yielding loop 19 424 939 times in 2 s and had not returned. A task that yields 1 000 times runs all 1 000 steps inside one call, so even a finite cooperative loop blocks the frame for its whole duration. The tokio and GLib executors bound a pass (tokio's coop budget, GLib's one dispatch per source per iteration); this pool should poll each task at most once per call and leave tasks woken during the pass for the next call, after waking the host. | `core/src/scheduler/local.rs:150-185`; verify13 `local_yield` |
| L3-RP3 | P3 (U32) | **The wire command-name table saturates for good.** `wire::command` leaks one `&'static str` per distinct name read off the wire and stops at 4 096. After that, every name not yet seen becomes `rustnative.wire.too-many-commands` for the life of the process, including names the application declares but had not used yet. A server or recording that sends 4 096 junk names breaks later real commands until restart. Interning only names the application registered (and refusing others) bounds it without the cliff. | `core/src/wire.rs:181-202` |

No new finding for U29 (every L0–L5 listener now has a token, or is test-only), U31 (the core's `RefCell` borrows in `Application::flush_state` and window close are not held across calls into the host), or U33 (L0–L5 queue no deferred writes).
