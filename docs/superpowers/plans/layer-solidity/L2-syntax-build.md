## Indicators added

- **L2.12 Total tooling parsers**: every function the LSP/build/CLI calls on user text (`compile`, `match_element`, `parse_markup`, `format_*`, `i18n::parse`, `Vocabulary::with_style_file`) returns `Ok`/`Err` for every prefix and every byte mutation of every repo source file — a property test over truncations + a fuzz target per entry. Catches F1 directly (the existing truncation test exists only for `sheet::parse`).
- **L2.13 Lowered output is valid Rust**: for every `.rsx` construct (incl. `pub`/`pub(crate)` modules, closures in conditions, generic fn signatures), `syn::parse_file(compile(x).code)` succeeds and the non-markup bytes are identical (byte-diff outside the inserted wrappers). Catches F2, F4, F5.
- **L2.14 Formatter preserves every non-whitespace token and every comment** (compare token streams and comment sets before/after `fmt`). Catches F3.
- **L2.15 Scanner ≡ parser**: for generated `.rsx` inputs, the element extents and Rust sub-streams `rsx_scan` finds equal those `syn` finds (differential). Catches F5.
- **L2.16 Hygiene fixture**: markup whose expressions name `__node`, `__layout`, `__children` behaves as plain Rust would (fails or refers to the user's own binding — never the macro's).
- **L2.17 Configuration errors are loud**: every reader of `rustnative.toml` (macros, `compile_styles`, `compile_messages`, `embed_resources`, CLI) reports a malformed file the same way; a test feeds each a broken file.
- **L2.18 Host/target correctness in build helpers**: decisions use `CARGO_CFG_TARGET_*`, never `cfg!` — a source test greps `rustnative-build` for `cfg!(` and the cross-build matrix (Linux→Windows, Windows→Android) checks the artifacts.
- **L2.19 Rebuild triggers name real inputs**: every `rerun-if-changed` path exists after the build (test: parse the build script's output, assert each path exists and is an input that was read).
- **L2.20 CLDR completeness**: every locale with a catalogue has plural rules (generated from vendored `plurals.xml`, or a build error); every translation supplies every category its locale uses for each plural selector.
- **L2.21 Generated identifiers are valid**: `syn::parse_str::<syn::Ident>` on every generated name (messages, resources), and a collision check.
- **L2.22 Monotonic store versions**: `versionCode(a) < versionCode(b)` whenever `a < b` in SemVer order (property), or an explicit override is required.
- **L2.23 Build helpers never ignore a write error** (U4 applied to build scripts specifically: stale output is a correctness failure, not a nuisance).

## Q-loop notes (iteration 1)

- New indicator *kind*: **tooling robustness under half-typed input** — the LSP and dev loop feed every intermediate keystroke to the same parsers; "rejects invalid input" is not enough, it must reject *every prefix* without panicking. Added as Q1g for every parser in L3–L10 (inspection decoders, wire formats, config readers).
- New *kind*: **host vs target** (F10) — anything that runs at build time decides for the target, not the machine. Re-asked for the CLI (L10) and the macros (style checks are already target-declared; resources were not).

| L2-F29 ✅ | P2 (i18n correctness) | **Term references are never checked, and terms do not fall back across locales.** Only message ids fall back. `write_pattern` looks a term up only in the bundle of the message being shown; the parser stores `{ -name }` unchecked while it checks `{ $name }`, and `messages::check` checks only variables. | L2-F30 ✅ | P2 (availability, U22) | **Term expansion costs exponential time and memory.** The `depth < 8` guard limits how deep terms nest, not how much they expand: a term that refers to itself k times expands to k⁸ copies. `Catalogues::with_file` applies a translator's edit to a running application, so a one-line `.ftl` change can stall or exhaust memory on the UI thread on every `format`.
