| L8-F1 | P2 | **A truncated disk-cache write breaks an image permanently.** `use_image` writes the downloaded bytes with `std::fs::write` (no temp or rename) and reads the cache before the network. A crash or a full disk mid-write leaves a truncated file. Decoding it fails `QueryError::fatal`, and with `stale_time(Duration::MAX)` the URL never recovers until someone clears the cache by hand. Write errors are discarded (`let _ =`). | `data/src/image.rs:185-210` |
| L8-F2 | P2 | **Image memory and disk are bounded by time only.** The in-memory cache is evicted by `retain_time`, not bytes (a documented `ponytail`), and the disk cache is never evicted at all. A long scroll through an image feed grows memory to whatever fits in five minutes, and disk without limit. There is no maximum encoded or decoded size before `decoder.decode`, so a decompression bomb (a 100 000 × 100 000 PNG of a few KB) is decoded at full size wherever the platform decoder does not honour `fit` first. | `image.rs` `retain_time`, `with_disk_cache`, `decode` |
| L8-F3 | P3 (security) | **Disk-cache keys are 64-bit FNV of the URL.** That hash is non-cryptographic with practical collisions, so a URL an attacker controls can be chosen to collide with another URL's cache file and serve its bytes for it (image cache poisoning). | `image.rs` `fnv(&url)` |
| L8-F4 | P3 | `chart.rs` has no `is_finite` or NaN handling. A NaN or infinite data point flows into layout and drawing as is; together with L5-F12, an infinite value makes the TUI rasterizer iterate a huge bound. To be verified in iteration 2. | `components/src/chart.rs` (`grep`) |
| L8-F5 | info (positive) | `Retry` retries only idempotent requests and only on transport failure, with bounded attempts. Query back-off saturates (`checked_shl`, `saturating_mul`). Images are decoded scaled to `fit` where the decoder supports it. | as cited |

## Indicators added (L8)

- **L8.1 Caches are crash-safe and bounded** (F1, F2): every disk cache writes temp → rename and verifies length or hash on read (a corrupt entry is deleted and refetched). Every cache has a byte budget with LRU eviction. A test kills the writer mid-write and asserts the image recovers on the next use.
- **L8.2 Decode limits** (F2): `ImageDecoder` rejects declared dimensions above a configured pixel budget before allocating. The fuzz corpus includes dimension bombs.
- **L8.3 Content-addressed cache keys** (F3): SHA-256 of the URL (or of the content).
- **L8.4 Non-finite data** (F4): every component that takes `f32`/`f64` data either rejects or clamps non-finite values at its constructor (`Scalar`-style). A property test feeds NaN and ±∞ through every chart, slider, and progress control.

| L8-F6 ✅ | **P1 (data loss)** | **`VersionedStore` destroys data on a rollback, and silently nulls any value that is not JSON.** (a) `load` returns `Ok(None)` when the stored `$version` is newer than this build's latest migration. After a rollback (the updater offers one: L5, L6-F7), the older application reads its saved state as *absent*, starts from its defaults, and its next `save` overwrites the newer data. The `down` transforms that `Migrations` requires are never used for this. | L8-F7 | P2 (data loss, U20) | **A load error empties the offline mutation queue and persisted tables, and the next write makes it permanent.** `QueryClient::with_offline_queue` and `LocalTable::persisted` both do `store.load(..).ok().flatten().and_then(decode.ok()).unwrap_or_default()`. | L8-F8 | P2 (data integrity) | **The native offline mutation queue has the same replay flaws as the web one (L7-F6).** A handler that returns `Unreachable` after the server applied the write (a lost response) gets requeued and replayed, so the effect happens twice. A mutation whose handler always answers `Unreachable` blocks every mutation behind it (`replay_next` stops at the head). | L8-F9 | P2 (data loss) | **Autosave overwrites changes made outside the application.** `DocumentController::autosave` saves when dirty and idle without consulting `external_change()` (which exists on the same type), so a file edited by another program, or synced in by a cloud client, is overwritten silently. `save_as` writes `<path>.saving` and renames it without `fsync` (U25), so a crash right after the rename can leave an empty document on file systems with delayed allocation. ### Indicators added (session 3)

- **L8.5 Version skew is a state, not an absence** (F6): a store reading data from a newer schema either migrates it down (the `down` transforms exist for this) or refuses to start and keeps the bytes untouched. A rollback test (v3 writes, v2 reads and saves, v3 reads) asserts nothing is lost.
- **L8.6 Opaque values pass through untouched** (F6b): a wrapper store never re-encodes a value it cannot parse. A property test pushes arbitrary bytes through every `StateStore` wrapper and asserts that they round-trip.

| L8-F11 ✅ | **P1 (availability)** | **Sorting a `DataTable` column that mixes numbers and text panics in `render`.** `sorted_order` compares two cells as `f64` when both parse and as lower-cased text otherwise. With mixed cells that is not a total order: `"2" < "10"` as numbers, `"10" < "1x"` and `"1x" < "2"` as text. Since Rust 1.81, `sort_by` may panic when it detects such a comparator. In the repro, 193 of 200 random 64-row columns mixing `"n"`, `"nx"`, and `"7n"` panicked. Real tables mix like this all the time ("N/A", "—", "3 kg" beside plain numbers), and the sort runs in `DataTable::render` whenever the person clicks a header, so a click turns into a component panic, and the panic policy then terminates or degrades the app (L6-F1, F2, F12). Each comparison also allocates two lower-cased strings and re-parses both cells: O(n log n) allocations on every render. Order numbers before text (or text before numbers), parse each cell once, and sort with `sort_by_cached_key`. | `components/src/widgets.rs:1037-1051, 1088`; `verify13/tests/table_sort.rs` |
| L8-F12 ✅ | P2 (security) | **`BearerAuth` sends the access token to whatever URL a request names, and endpoint parameters are spliced into the path unescaped.** `HttpClient::url` passes an absolute `http://` or `https://` URL through unchanged, and `BearerAuth::intercept` adds `Authorization` to every request without checking the origin against the client's base. ### Indicators added (iteration 3)

- **L8.7 Comparators are total orders** (F11): every comparator in the framework gets a property test over generated mixed inputs that checks antisymmetry and transitivity, and runs on CI under the standard library's order check.
- **L8.8 Credentials follow origins** (F12): an interceptor that adds credentials checks the request's origin against the client's configured origins and refuses `http:` unless the configuration allows it. A test sends a request to a foreign host and asserts no `Authorization` header.
- **L8.9 Invalidation is versioned** (F13): every cached key carries a generation that `invalidate` bumps and `settle_fetch` compares. A virtual-time test interleaves a slow fetch, a mutation, and the settle in every order and asserts the final state equals the server's.
