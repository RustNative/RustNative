| L8-F1 | P2 | **A truncated disk-cache write breaks an image permanently.** `use_image` writes the downloaded bytes with `std::fs::write` (no temp or rename) and reads the cache before the network. A crash or a full disk mid-write leaves a truncated file. Decoding it fails `QueryError::fatal`, and with `stale_time(Duration::MAX)` the URL never recovers until someone clears the cache by hand. Write errors are discarded (`let _ =`). | `data/src/image.rs:185-210` |
| L8-F2 | P2 | **Image memory and disk are bounded by time only.** The in-memory cache is evicted by `retain_time`, not bytes (a documented `ponytail`), and the disk cache is never evicted at all. A long scroll through an image feed grows memory to whatever fits in five minutes, and disk without limit. There is no maximum encoded or decoded size before `decoder.decode`, so a decompression bomb (a 100 000 × 100 000 PNG of a few KB) is decoded at full size wherever the platform decoder does not honour `fit` first. | `image.rs` `retain_time`, `with_disk_cache`, `decode` |
| L8-F3 | P3 (security) | **Disk-cache keys are 64-bit FNV of the URL.** That hash is non-cryptographic with practical collisions, so a URL an attacker controls can be chosen to collide with another URL's cache file and serve its bytes for it (image cache poisoning). | `image.rs` `fnv(&url)` |
| L8-F4 | P3 | `chart.rs` has no `is_finite` or NaN handling. A NaN or infinite data point flows into layout and drawing as is; together with L5-F12, an infinite value makes the TUI rasterizer iterate a huge bound. To be verified in iteration 2. | `components/src/chart.rs` (`grep`) |
| L8-F5 | info (positive) | `Retry` retries only idempotent requests and only on transport failure, with bounded attempts. Query back-off saturates (`checked_shl`, `saturating_mul`). Images are decoded scaled to `fit` where the decoder supports it. | as cited |

## Indicators added (L8)

- **L8.1 Caches are crash-safe and bounded** (F1, F2): every disk cache writes temp → rename and verifies length or hash on read (a corrupt entry is deleted and refetched). Every cache has a byte budget with LRU eviction. A test kills the writer mid-write and asserts the image recovers on the next use.
- **L8.2 Decode limits** (F2): `ImageDecoder` rejects declared dimensions above a configured pixel budget before allocating. The fuzz corpus includes dimension bombs.
- **L8.3 Content-addressed cache keys** (F3): SHA-256 of the URL (or of the content).
- **L8.4 Non-finite data** (F4): every component that takes `f32`/`f64` data either rejects or clamps non-finite values at its constructor (`Scalar`-style). A property test feeds NaN and ±∞ through every chart, slider, and progress control.

| L8-F6 ✅ | **P1 (data loss)** | **`VersionedStore` destroys data on a rollback, and silently nulls any value that is not JSON.** (a) `load` returns `Ok(None)` when the stored `$version` is newer than this build's latest migration. After a rollback (the updater offers one: L5, L6-F7), the older application reads its saved state as *absent*, starts from its defaults, and its next `save` overwrites the newer data. The `down` transforms that `Migrations` requires are never used for this. (c) `open` reads any non-envelope bytes as `(1, Null)` (U20 three times in one type). | `data/src/migrate.rs` `VersionedStore::{load,save}`, `open`; verify11 |
| L8-F7 | P2 (data loss, U20) | **A load error empties the offline mutation queue and persisted tables, and the next write makes it permanent.** `QueryClient::with_offline_queue` and `LocalTable::persisted` both do `store.load(..).ok().flatten().and_then(decode.ok()).unwrap_or_default()`. A transient read error (a locked file) or a schema change starts with an empty queue or table, and the next `persist_queue` or save writes it over the stored one. `persist_queue` also saves `[]` when serialisation fails (`unwrap_or_default`) and only `eprintln!`s a save failure. | `data/src/mutation.rs` `with_offline_queue`, `persist_queue`; `table.rs:65-72` |
| L8-F8 | P2 (data integrity) | **The native offline mutation queue has the same replay flaws as the web one (L7-F6).** A handler that returns `Unreachable` after the server applied the write (a lost response) gets requeued and replayed, so the effect happens twice. Queued mutations carry no idempotency key, owner, or expiry, and they are stored under one global key (`OFFLINE_QUEUE_KEY`), so after a sign-out they replay in the next user's session. A mutation whose handler always answers `Unreachable` blocks every mutation behind it (`replay_next` stops at the head). | L8-F9 | P2 (data loss) | **Autosave overwrites changes made outside the application.** `DocumentController::autosave` saves when dirty and idle without consulting `external_change()` (which exists on the same type), so a file edited by another program, or synced in by a cloud client, is overwritten silently. `save_as` writes `<path>.saving` and renames it without `fsync` (U25), so a crash right after the rename can leave an empty document on file systems with delayed allocation. ### Indicators added (session 3)

- **L8.5 Version skew is a state, not an absence** (F6): a store reading data from a newer schema either migrates it down (the `down` transforms exist for this) or refuses to start and keeps the bytes untouched. A rollback test (v3 writes, v2 reads and saves, v3 reads) asserts nothing is lost.
- **L8.6 Opaque values pass through untouched** (F6b): a wrapper store never re-encodes a value it cannot parse. A property test pushes arbitrary bytes through every `StateStore` wrapper and asserts that they round-trip.
