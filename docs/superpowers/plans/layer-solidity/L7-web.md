## Indicators added (L7)

- **L7.1 URL-context safety** (F1): every URL-valued attribute (`href`, `action`, `src`, `formaction`, `poster`) is passed through one `SafeUrl` type that allows `http`, `https`, `mailto`, `tel`, and relative URLs, and refuses `javascript:`, `data:` (except images), and `vbscript:`, after the WHATWG URL parser's normalisation (leading whitespace and control characters, mixed case, entity forms). It is a type, so a raw `&str` cannot reach an `href` (E5). The test corpus is the OWASP XSS filter-evasion URL list, run through the server and through the client realizer in a browser.
- **L7.2 CSS value grammar** (F2, L1): every value emitted into CSS goes through one serializer per CSS type (`<family-name>` as a CSS string with `\` escapes, colours, lengths), never `format!` of raw text. The test feeds `}`, `;`, `/*`, `\`, `</style>`, and newlines through every style property and asserts the parsed stylesheet's rule count is unchanged.
- **L7.3 Name validation** (F3): `Element::attr`/`set` reject names outside the HTML attribute-name grammar and refuse `on*` unless explicitly unsafe-marked.
- **L7.4 Generative translator equivalence** (F4): a program generator over the client subset (arith on every width, string methods on random Unicode, including astral and combining characters, collections, control flow, panics), run in Rust and in Node. Any difference in result or failure is a failure, 10 000 programs per CI run, with Node required.

| L7-F6 | **P1 (data integrity, security)** | **The offline call queue replays `/_fn/` POSTs without idempotency, without expiry, and under whoever is signed in later.** `sw.js` `call()` queues any server-function POST whose `fetch` *rejects*, including a request that reached the server and whose response was lost on a flaky connection. `replay()` sends it again with the saved headers. Nothing marks a call as a replay or gives it an idempotency key, so non-idempotent server functions (a payment, a message, an order) run twice. The stored `at` is never checked, so a call queued days ago is delivered whenever the device next comes online. Replay uses `credentials: "same-origin"`, that is, the cookies *at replay time*, together with the *saved* `x-csrf-token`. The `__Host-csrf` cookie is issued per browser and survives sign-out (server `app.rs`: issued only when absent), so on a shared device the double-submit check passes, and user A's queued actions execute in user B's session after B signs in. The queue has no size bound, and `replay` stops at the first network error. | `web/src/runtime/sw.js` `call`, `replay`; `rn.js` `serviceWorker` (`rn:replay` on `online`); `server/src/app.rs` CSRF cookie issue (confirmed by reading) |
| L7-F7 | P2 (privacy) | **The service worker caches personalised pages that the server marked `no-store`.** On every navigation, the fetch handler stores each successful response in the `rn-pages` cache. That cache is not versioned and is never purged, not on sign-out and not on a new build. `web.rs` `html_headers` sets `Cache-Control: no-store` precisely because "a page carries the request's nonce and token: never shared"; the worker ignores it. Offline, or whenever the network fails (which an attacker on a shared machine can force), the next person gets the previous user's pages, with their data and CSRF token, from `caches.match`. | `sw.js` `fetch` handler (`PAGES`); `server/src/web.rs` `html_headers` |
| L7-F8 | P2 (privacy, security) | **Server-interactive mode ships the root component's inspector state to every browser.** Every Live `dom` and `drain` frame carries `root_snapshot(&tree)`, which is the root component's `Component::inspect()` value. Its contract says it is "state as the inspector shows it" (`core/src/component/mod.rs:154-158`). A developer who implements `inspect` to debug server-side state (a user record, an internal token) publishes it to the client on every frame. `rn.js` keeps it, sends it back in `hello` (where L9-F2 trusts it), and stores it in `sessionStorage` through `saveEntry`. Server-interactive mode exists so that state stays on the server. | `sync/src/live.rs:419-424, 496-528`; `rn.js` `LiveIsland.receive` (`dom`, `drain`), `saveEntry` |
| L7-F9 | P3 | **Web runtime details.** The service worker and the manifest are registered with scope `/` even when the application is mounted under `ServerApp::prefix`, so one application's worker intercepts every application on the origin (U23). `persist` islands load `localStorage["rn:persist:<name>"]` without any user or session key, so on a shared browser the next user starts from the previous user's state. Client navigation (`go`) adopts each visited page's `<style>` text into `document.adoptedStyleSheets` and never removes it, so rules from earlier pages keep applying, and the set grows for the life of the tab. `Effects::db_put` keys storage as `db/{store}/{key}`, so `("a/b", "c")` and `("a", "b/c")` collide, and it drops serialisation and storage errors (U20, U4). On native, `open_file` answers `None`, the same answer as a cancel, when the capability is missing. A static export joins developer-supplied route paths and module names onto the output folder unchecked (`"../x"` writes outside it, U26), writes non-atomically (U25), and never removes stale files. | `web/src/pwa.rs` `manifest`; `rn.js` `serviceWorker`, `start` (`persist`), `adoptCss`, `go`; `web/src/capability.rs` `db_put`, `open_file`; `web/src/export.rs` `export`, `page_file` |

### Indicators added (session 3)

- **L7.5 Offline writes are idempotent and owned** (F6): every queued call carries an idempotency key the server deduplicates, the principal it was queued under (dropped if the session changed), and an expiry. A test loses a response after the server has applied a call and asserts that the effect happens once.
- **L7.6 The service worker obeys the server's cache policy** (F7): no response with `no-store` or `private` enters any cache. Sign-out clears every page cache and queue. A test signs in, browses, signs out, goes offline, and asserts that no page of the first user is served.
- **L7.7 What reaches the client is declared** (F8): Live sends only what a component explicitly marks client-visible (a `ClientState` type), never the inspector view. A test with a server-only field asserts that it never appears in a frame.
| L7-F10 | P3 | **Translator and image details.** `emit::ident` renames a reserved JavaScript name by appending `_` (`rn` → `rn_`, `this` → `this_`), so a Rust program with both `rn` and `rn_`, or `this` and `this_`, compiles to one JavaScript variable: a silent miscompile that the subset refuses nowhere. `ident_field` does not rename at all, so a field named `__proto__` becomes a prototype write through `w(object, "__proto__", …)`. `image::resize` multiplies pixel coordinates in `u32` (`y * source_height`, `(source_y * source_width + source_x) * 4`, `width * height * 4`), which overflows for images above about 65 536 px on a side: a panic in debug, or wrong pixels read in release, on the server's image-variant path (U22). | `webgen/src/emit.rs:69-135`; `webgen/src/expr.rs:1451-1454`; `web/src/image.rs` `resize` |
