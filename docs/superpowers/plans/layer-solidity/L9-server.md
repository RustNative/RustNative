## Indicators added (L9)

- **L9.1 Session capability** (F1): a Live session id is ≥ 128 bits from the OS RNG, and resuming requires the same authenticated principal (the session cookie's id) that created it. A test from a second client with a guessed or observed id gets a fresh session, never the victim's tree.
- **L9.2 Nothing the client sends becomes trusted state** (F2): snapshots are sealed (AEAD with the server key, carrying session id and expiry); an unsealed or tampered snapshot is refused. A property test over arbitrary JSON snapshots asserts the root never starts from client JSON.
- **L9.3 Server-side event authorization** (F3, L3-F12): before `update`, the server checks that the target exists in the tree **it last sent** and is enabled, visible, and owned by this session. A conformance case sends events at disabled, hidden, removed, and never-rendered keys, and asserts that `update` never runs.
- **L9.4 Per-principal resource bounds** (F4): per-client caps on sessions, frames per second, and frame bytes, with documented defaults. A load test from one address cannot exhaust `max_sessions` for others.
