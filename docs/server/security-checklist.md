# Server security checklist

`PLAN.md` Milestone 49. These defaults are on unless an application turns
them off (`Security`). Shipping without one of them is a defect, not a
missing feature. Each line names the test that holds it.

| Protection | Default | Test (`crates/rustnative-server/tests/`) |
|---|---|---|
| Request forgery: unsafe methods need the double-submit token (`__Host-csrf` cookie, sent back as `X-CSRF-Token` or the form's `_csrf`); the only exceptions are routes declared `csrf_exempt` and requests that present a bearer token *and no cookies* (no ambient credential to forge with) | on | `app.rs` `unsafe_requests_need_the_forgery_token` |
| JSON bodies: the `Json` extractor refuses a body whose `Content-Type` is not `application/json` or `application/…+json` with `415`, so a cross-site "simple" request (`text/plain`, no preflight) never reaches a JSON handler — `csrf_exempt` routes included | on | `deploy.rs` `a_json_body_must_say_it_is_json` |
| Content security policy: `default-src 'self'`, scripts and styles only with the response's nonce, no objects, no framing, `base-uri 'none'`, `form-action 'self'`; a fresh nonce per response | on | `app.rs` `every_response_carries_the_security_headers` |
| Security headers: `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`, HSTS; cross-origin isolation is opt-in | on | same |
| Cookies: `Secure; HttpOnly; SameSite=Lax; Path=/` by default; the session and CSRF cookies use the `__Host-` prefix | on | `auth.rs` `a_session_signs_in_and_policies_guard_routes`; `Cookie` doc test |
| Sessions: sealed with AES-256-GCM, so they cannot be read or forged; a tampered cookie is no session. Keys rotate without signing anyone out (`with_previous_keys`), and every session has an id and issue time an application revokes against (`with_revocation`) | on | `auth.rs` same test, `a_rotated_key_keeps_sessions_and_reseals_them`, `a_revoked_session_opens_as_none` |
| Rate limiting: a token bucket per client, 120 a minute; `429` with `Retry-After`. The client is the peer, or — behind a trusted proxy (loopback by default; `Security::trusted_proxies`) — the nearest untrusted address it forwarded, so a client cannot pick its own bucket and a proxy does not put everyone in one; serverless hosts report the caller (`sourceIp`, `REMOTE_ADDR`) | on | `app.rs` `clients_are_rate_limited_and_bodies_bounded`; `security.rs` unit tests |
| Request size: bodies over 1 MiB are `413` before a handler sees them | on | same |
| Output escaping: `Html` escapes all text; unescaped markup is only a `&'static str` written in the source | by construction | `Html` doc test; `app.rs` form test; `platform.rs` admin test |
| Error pages: a server error's detail is logged, never shown | on | `app.rs` `error_pages_follow_accept_and_hide_internals` |
| Authorization: every route states its access (`public`, `signed_in`, `authorized::<Policy>`); a route that does not is a compile error | by type | `handler` compile-fail doc test; `auth.rs` |
| Passwords: Argon2id with a random salt, in PHC format | on | `password` doc test |
| Passkeys: the challenge is issued and remembered by the server and accepted once (a stateless session cannot make it single-use); origin, relying party, user presence, and user verification checked; a counter that does not advance is refused | on | `auth.rs` `a_passkey_registers_then_signs_in_once_per_counter`, `a_synced_passkey_s_assertion_cannot_be_replayed` |
| Response cache: a response marked `no-store` or `private` — every rendered page, which carries its request's nonce and forgery token — is never stored; entries vary by `Accept-Language` and `Accept`; the cache is bounded | on | `deploy.rs` `a_response_carrying_one_visitor_s_secrets_is_never_replayed_to_another`, `cached_responses_vary_by_language`; `cache.rs` unit tests |
| Federation: PKCE (S256) and a checked state | on | `auth.rs` `federation_uses_pkce_and_checks_the_state` |
| Row policies: reads through `RowPolicies` are limited to what the principal may see | when declared | `data.rs` `row_policies_hold_for_queries_and_single_rows` |
| SQL: queries are bound parameters; `query!` is checked against the schema at compile time; the admin surface takes names only from the model | by construction | `server-demo` compile-fail doc test; `platform.rs` admin test |
| Secrets: `Secret<T>` never prints or serializes its value, and there is no global configuration | by type | `config` doc test |
| Operational endpoints: `/healthz`, `/readyz` (feature `health`) and `/metrics` (feature `metrics`) answer anyone who reaches the port, unauthenticated; they carry counters and a readiness list, no request data. Turn the features off, or keep them off the public path at the proxy (as the exported Compose, Kubernetes, and systemd units leave the port behind one), where the counts themselves are sensitive | on, when the features are | `app.rs` `health_metrics_and_the_report` |
| Deploy control API (`rustnative deploy local`): loopback only; every route needs the run's random token (`Authorization: Bearer`, constant-time compare; the token is in a `0600` file in a per-user directory); `Host` must be `127.0.0.1:<port>` or `localhost:<port>` (DNS rebinding); a request carrying `Origin` or a `Sec-Fetch-Site` other than `none` (a web page) is refused | on | `deploy.rs` `a_cross_site_page_cannot_redirect_the_deployment`, `the_control_api_needs_this_run_s_token`, `the_control_api_answers_only_its_own_loopback_name`, `the_control_api_drives_the_same_adapter`; CLI `deploy.rs` `the_local_control_api_answers_only_this_user_s_cli` |
